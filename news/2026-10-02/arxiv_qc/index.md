<h2>論文1: 3つのフレームワークで量子コード生成を測るベンチマーク</h2>
<p><strong>出典:</strong> QuanBench+: A Unified Multi-Framework Benchmark for LLM-Based Quantum Code Generation. <a href="https://arxiv.org/abs/2604.08570">arXiv:2604.08570</a> (2026, v2).</p>
<p>既存の量子コード生成ベンチマークの多くが単一のフレームワークに閉じている中で、課題の意図を固定したまま実装先だけを変え、量子の推論の誤りとAPIへの不慣れを切り分けようとしている点が、今日の基準点として適しているので選んだ。著者はベイルート・アメリカン大学のAli Slim氏ら6人と、アブドラ王立科学技術大学（KAUST）のHasan Abed Al Kader Hammoud氏、Bernard Ghanem氏で、初版は2026年3月25日の投稿である。課題は既存のQuanBenchから、数値的・機能的に正否を判定できるものを残し、フレームワーク間で確実に採点できなかった2課題を除いた42課題で、量子アルゴリズム、ゲート分解、状態準備の3分類からなる。各課題をQiskit、PennyLane、Cirq向けに書き分け、正解コードの出力をすべて計算基底上の測定確率の配列にそろえた。採点は実行ベースのPass@kで、確率的な出力には正解分布との間のKLダイバージェンス（平滑化した後で閾値0.05）を使う。著者らは、測定統計が同じでもユニタリ全体の重なりが小さい回路は多いため、プロセス忠実度は正しい解を落とす偽陰性を生むとして、正否の基準から外した。Pass@1は温度0の貪欲生成で1回、Pass@5は温度0.8で5回生成する。さらに、実行時例外ならトレースバックを、出力が誤りならその旨を返し、最大5回まで書き直させるフィードバック修復も評価した。実行環境はPython 3.10、Qiskit 0.46.0、Cirq 1.6.1、PennyLane 0.43.1に固定している。</p>
<p>1回の生成での最高Pass@1は、Qiskitで59.5%、Cirqで54.8%、PennyLaneで42.9%で、フィードバック修復を入れると最高値はそれぞれ83.3%、76.2%、66.7%に上がった。平均の首位はQiskitとCirqで強いGemini 3 Proで、PennyLaneの1回生成ではGPT-5.1が最高だった。ほぼすべてのモデルでQiskitが最も高くPennyLaneが最も低いことから、著者らは、同じ課題でも成績がフレームワークへの習熟に強く依存し、移植可能な量子プログラミング能力はまだ十分でないと結論する。インポートや関数の枠組みを先に与えるプレフィルは、主に小・中規模のモデルで効き、境界部分の書き損じを減らすが、意味的に難しい課題は解決しない。修復後に残る失敗は、APIの誤用ではなく、アルゴリズムの構造や測定の論理といった深い意味的な誤りが中心になる。限界として、課題が42と少なく、量子アルゴリズムの課題が状態準備や分解より多いため総合値がその分類に引っ張られること、正解コードをフレームワーク間で移植する際の微妙な不一致、古いAPIを再現して実行に失敗する場合に意図は正しくても不正解になることを、著者ら自身が挙げている。評価は無雑音シミュレータでの出力分布に限られ、回路の深さやゲート数といった資源は採点対象に入っていない。</p>
<h2>論文2: バグ注入から修復検証まで自動化する量子デバッグ評価</h2>
<p><strong>出典:</strong> QBugLM: An Agentic Benchmarking Framework for LLM-based Quantum Software Debugging. <a href="https://arxiv.org/abs/2606.07314">arXiv:2606.07314</a> (2026).</p>
<p>量子ソフトウェアのバグは例外を出さずに誤った分布を返すことが多く、9月30日に扱ったベンチマークでもデバッグ課題は多くのモデルで0点だった。そのデバッグを、バグの注入から修復の正否判定まで人手を介さずに回す評価枠組みとして、論文1のコード生成と対になるので選んだ。著者はメルボルン大学とオーストラリア連邦科学産業研究機構（CSIRO）Data61のAn B. B. Pham氏、Hoa T. Nguyen氏、Muhammad Usman氏の3人で、2026年6月5日の投稿である。枠組みは4つの部品からなる。QBugGenは、既存研究と過去のベンチマークで報告されたLLM生成コードの失敗を整理した、構造的誤り、意味の逸脱、廃止された構文、ゲートの過剰使用の4分類に基づき、正しいOpenQASM 3.0プログラムにバグを1つだけ系統的に注入し、変異の種類と行を正解ラベルとして記録する。QBugFindのLLMエージェントは仕様とバグ入りのコードから、バグのある行と分類を報告し、QBugFixの別のエージェントがその報告を受けて修正版を書く。QBugCheckは、無雑音シミュレータで1,024ショット実行した測定分布の全変動距離が閾値以下で、かつ同じ最適化レベルでトランスパイルしたゲート数が正解と一致することを合格条件にする。</p>
<p>$$
\delta(P_{\mathrm{ref}}, P_{\mathrm{fixed}}) = \frac{1}{2}\sum_k \left| P_{\mathrm{ref}}(k) - P_{\mathrm{fixed}}(k) \right| \le 0.05, \qquad |G_{\mathrm{ref}} - G_{\mathrm{fixed}}| \le 0
$$</p>
<p>対象はMQT Benchの5量子ビット回路5種（ドイチュ・ジョザ、グローバー、ベルンシュタイン・ヴァジラニ、GHZ状態、W状態）で、モデルはClaude Sonnet 4.6とQwen3 Coder Next、試行は初回と再試行2回の計3回、各設定を5回独立に実行した。ベルンシュタイン・ヴァジラニ回路でのPass@1は、構造化した単純なプロンプトでSonnet 4.6が97%、Qwen3が95%だったのに対し、思考の連鎖（CoT）ではそれぞれ90%と45%、ReActでは95%と63%に下がった。両モデルとも推論機能を内蔵しているため、明示的な推論の足場が資源を固定した条件ではかえって性能を落とした、と著者らは解釈している。再試行なしでは、Qwen3が意味の逸脱・廃止構文・過剰使用で20%、Sonnet 4.6はこの3分類で0%、構造的誤りは両者60%だったが、1回の再試行で全体のPass@1は25%未満から80%超に上がった。再試行2回の後も、Sonnet 4.6は構造的誤りで80%、Qwen3は意味の逸脱で92%にとどまり、モデルごとに別の弱点が残った。費用は、構造的誤り、廃止構文、過剰使用で、Qwen3が1変異あたり0.042、0.036、0.061ドル、Sonnet 4.6が0.202、0.327、0.496ドルで4.8〜9.1倍の差があり、構造的誤りの所要時間は127.6秒対28秒だった。意味の逸脱だけは逆で、Qwen3が平均約35万トークン（0.198ドル）を使っても92%、Sonnet 4.6は約9.1万トークン（0.369ドル）で100%だった。限界として、5量子ビットの5回路、1変異あたりバグ1つという設定は実際のバグの分布から遠く、変異戦略の多くが意味の逸脱に属するため他の分類の値は1回の失敗で大きく動く。ゲート数の許容差を0にしているため、分布は正しいがゲート数の異なる修正は不合格になる。通信の時間切れや文脈長の超過も失敗に数えており、著者らはこれを実運用に近い保守的な推定と位置づけている。</p>
<h2>論文3: 記憶と得点差フィードバックで言語モデルに回路を探索させるテスト時学習</h2>
<p><strong>出典:</strong> Quantum Circuit Generation via test-time learning with large language models. <a href="https://arxiv.org/abs/2602.03466">arXiv:2602.03466</a> (2026, v5).</p>
<p>学習データも微分可能なシミュレータも使わずに、重みを固定したLLMを推論時の文脈だけで最適化器として働かせ、20〜25量子ビットという従来の機械学習型回路合成（拡散モデルで9量子ビットまで、強化学習で4〜6量子ビット）より大きな規模で、どの部品が探索を支えているかをアブレーションで切り分けているので選んだ。著者はパレルモ大学工学部のAdriano Macarone-Palmieri氏とRosario Lo Franco氏の2人で、初版は2026年2月3日の投稿である。課題は、ゲートをH、CNOT、RYに限り、RYの角度を3度・10度・25度（非Clifford実験では0.1、0.42、1.0ラジアン）に離散化した固定長のゲート列を書き換えて、出力状態のMeyer-Wallach大域もつれ量Qを最大化することである。ゲートの追加・削除は禁止し、置き換えだけを許すことで、CNOTを足し続けてQを上げる退化した解を防いでいる。評価は厳密な状態ベクトル計算で、1回の評価に量子ビット数nに対して2のn乗のメモリを要するため、評価回数あたりの効率が問題になる。</p>
<p>$$
Q(\psi) = \frac{4}{N}\sum_{i=1}^{N}\left(1 - \mathrm{Tr}\left[\rho_i^{2}\right]\right)
$$</p>
<p>部品は3つある。これまでの最良回路を毎回プロンプトに入れるエピソード記憶、直前の提案でQがいくつ上下したかを「0.12改善した」のような文で返す得点差フィードバック、探索が停滞したら最良回路から再出発するリスタートである。20量子ビットでは、GPT 5.1にエピソード記憶だけを与え、ゲート数を25〜45で変えると、最良でQ=0.99に達したが、Q&gt;0.8の成功率は約10%だった。25量子ビット・35ゲートでは記憶だけの場合Q≈0.48で頭打ちになり、GPT 5.2に3部品すべてを与え、15ステップ×3回のリスタートで計45回の評価に制限すると、11回の実行のうち7回でQ≥0.92、複数回でQ=1.0に達した。同じ45回の予算でランダムな書き換えの山登り法を回すと、初期Q≈0.02から始めた10回では0.16を超えず、初期0.08からでも最良0.29だった。得点差フィードバックを外すと実行間のばらつきが増え、Qが0.24や0.43で終わる回が出たのに対し、リスタートを外した影響は小さかった。記憶を外した場合は独立サンプリングに戻るため、著者らは評価回数の面で現実的でないとして独立の列を設けていない。初期回路のQが約0.45以上なら1回のクエリで高い値に届く一方、ある種の接続形は再出発しても抜けられない停滞点になり、その原因は分かっていない。得られた高得点の状態の多くは、ベル対と小さなGHZ状態の積のような安定化子状態やグラフ状態に近く、著者らはこれをQという指標の性質とLLMが持つ量子回路の事前知識の両方の反映とみている。小規模なオープンモデルではCNOTを梯子状に並べた解しか出なかった。限界として、目的関数がQの1種類で、その最大値は既知の構成で達成できる。評価は無雑音で、ハードウェアの接続制約やゲートの誤り率は入っておらず、成功の閾値（Q≥0.8）と11回という試行数も小さい。</p>
<h2>論文4: 文献検索と専門家役の議論を組み込んだ変分量子回路の自律設計</h2>
<p><strong>出典:</strong> An LLM System for Autonomous Variational Quantum Circuit Design. <a href="https://arxiv.org/abs/2606.13380">arXiv:2606.13380</a> (2026).</p>
<p>量子機械学習の特徴マップと量子化学のアンザッツという性質の異なる2課題を同じエージェント系で設計させ、文献に基づく批評の工程を加えた効果をアブレーションで示している、日本のグループによる研究なので選んだ。著者は大阪大学量子情報・量子生命研究センターのKenya Sakka氏、Wataru Mizukami氏、Kosuke Mitarai氏の3人で、2026年6月11日の投稿である。同じグループの先行研究は特徴マップの設計に限られ、初期案をLLMの内部知識だけで作っていたため、案の質がばらつき、見込みの薄い方向に計算を使うことがあった。今回の系は7つの部品からなる。最初の1回だけ動く探索部はo3-deep-researchがウェブ検索で調査報告を作り、種となる案を10、5、2と段階的に絞る。生成部はGPT-5が案と数式を書き、議論部では批評役が専門家役（例えばVQEの表現力と対称性の専門家）に質問し、quant-phの2,785本（2013年1月〜2025年4月）を埋め込んだベクトルデータベースから1問あたり最大3本の論文を引いて答えさせ、擁護役が批評を採るか退けるかを判断して案を直す。これを最大3回繰り返す。検証部はPennyLane 0.39.0のソースから作った385クラスの文書で引数の使い方を静的に照合したうえで、ダミーデータで実行し、最大3回まで修正させる。評価部と講評部が結果と資源量を次の試行へ返し、これを15試行回す。</p>
<p>特徴マップでは、特徴マップ内の非線形な古典変換と学習パラメータを禁止して量子側の埋め込みだけを設計対象にし、MNISTでSVMの精度を評価した。最良の特徴マップは試行4で得られ、10量子ビットでは代表的な量子特徴マップと先行研究の系のすべてを、MNIST、Fashion-MNIST、CIFAR-10の全データセットで上回り、14量子ビットにすると古典のRBFカーネルも上回った。量子ビット数を2から14まで変えても生成コードはそのまま動き、6量子ビットで既に10量子ビットの比較対象を上回った。アンザッツでは、H₂、H₄、H₆、LiH、BeH₂、H₂O、N₂の7分子（STO-3G、ジョルダン・ウィグナー変換）を各10通りの結合長で解き、厳密エネルギーとの平均絶対誤差を目的にした。ADAPT-VQEのように回路を逐次伸ばす方式は除き、ゲート数とパラメータ数が量子ビット数の2乗以下で増えることを条件にしたため、UCCSDは設計空間の外になる。最良のアンザッツ（試行14）の平均誤差は6.4ミリハートリーで、化学的精度の1.6ミリハートリーには届かないが、伸ばしたH₆とN₂の一部を除くほぼ全点で化学的精度に入った。パラメータを多めに与えたハードウェア効率型と比べると、GateFabricには劣り、Particle U1とU2にはおおむね勝った。BeH₂、H₂O、N₂の長い結合長ではUCCSDを上回る一方、水素鎖ではUCCSDなど化学由来のアンザッツより精度が低い。アブレーションでは、探索部を入れると特徴マップの試行1の精度が0.8567±0.0626から0.9562±0.0026へ上がりばらつきも縮んだが、初期性能と最終性能の相関はほぼ0で、著者らは効果の中心を初期値ではなく探索の安定化に置く。議論部を単一LLMの自己反省や改良なしに置き換えると最終性能は下がったが、各条件5回の実行による予備的な結果である。限界として、粒子数・スピン・空間対称性の保存は講評の文章で指示しただけで数値として返していないため、生成回路はこれらを一貫しては満たさなかった。VQEは単一の乱数シードでの1回の最適化で、すべて無雑音の状態ベクトル計算であり、実機の接続や雑音を考慮した生成は今後の課題とされている。生成された回路の構造から一般的な設計原理を引き出すのは難しかった、と著者ら自身が述べている。</p>
<h2>論文5: 技術仕様を介して論文から量子多体計算プログラムを作る</h2>
<p><strong>出典:</strong> From Paper to Program: Specification-Guided Implementation of Quantum Many-Body Algorithms with Large Language Model. <a href="https://arxiv.org/abs/2604.04089">arXiv:2604.04089</a> (2026, v7).</p>
<p>LLMに論文を直接渡して実装させる方式と、論文と実装の間に人が監督してレビューした技術仕様を挟む方式を、複数のモデルと実行環境で同じ物理的基準により比べ、仕様の効果とモデルの実装力という2つのボトルネックを分けて示しているので選んだ。量子計算機そのものではなく量子多体系の古典数値計算が対象だが、生成AIが量子物理の論文をコードにする際の失敗の構造を具体的に記録している。著者は中国科学院物理研究所のYi Zhou氏の単著で、初版は2026年4月5日の投稿で、ここでは題名と内容を改めた9月26日の第7版を読む。役割は、論文から理論文書を起こす抽出役、それを方程式単位で点検してテンソルの形、縮約の順序、ゲージの選択、フェルミオン符号、メモリ量、検証テストを書き出す仕様役、研究室主宰者の視点で仕様の欠落を「明確・要修正・欠落」に分類するレビュー役、Pythonで実装する実装役の4つで、人間の主宰者は課題の選択と物理量の判定だけを行い、コードを読んでバグの位置を教えることはしない。実装中に前提となる検査が通らなければ先へ進ませない停止ゲートも仕様に含める。</p>
<p>1つ目の事例は、Schollwöckの約100ページのレビューから2サイトの行列フリーDMRGを実装する課題で、スピン1/2ハイゼンベルク鎖とスピン1のAKLT鎖を対象にした。論文を直接渡した13回では6回が合格し、Geminiは3回すべて、Claudeは4回中3回で合格した一方、GPTとKimiは各3回とも有効ハミルトニアンを密行列として作りメモリ不足に陥った。仕様を介すと、4つの仕様モデル×4つの実装構成の16通りすべてが合格し、GPT 5.4が仕様を数式なしの英文に書き直した版でも2回とも合格した。合格例はハイゼンベルク鎖の熱力学極限のエネルギー密度を−0.4427と出し（ベーテ仮説の値は−0.4431）、AKLT鎖の厳密な基底エネルギー、エンタングルメントエントロピーln 2、ストリング秩序−4/9を再現した。2つ目の事例は、著者自身が共著者である5ページのレターにある、HFB状態をパフィアンの重なり積分から1テンソルずつMPSに変換する手法で、60サイトのキタエフ鎖で対形成の強さ0.2以上の全点でサイトあたりのエネルギー誤差10のマイナス5乗未満を合格条件にした。論文を直接渡した11回は0回、同じモデルが仕様も実装も担う11回は4回（Codex上とOpenCode上のGPT 5.5、ClaudeCode上とOpenCode上のClaude Opus 4.8）、他モデルの仕様を使う8回は4回、それまでの実装記録を統合した最終仕様では7回中3回が合格し、全体では26回中11回（約42%）だった。仕様の受け渡しは非対称で、Codex上のGPT 5.5は他の4モデルが書いた仕様すべてで合格したが、逆方向の4回はいずれも失敗した。失敗例には、相関行列から得た厳密エネルギーをMPSのエネルギーとして報告する、4サイト以下の厳密検査には通るが5サイト以上で破綻する、といったものがあり、著者らはこれを観測量の出所、規模の検証、符号規約の一貫性、中間縮約の再利用という4つの検証規則にまとめた。限界として、比較は予算をそろえた実験ではなく、直接実装には約20回や30回の打ち切りがある一方、仕様経由の多くの実行には人の介入回数の上限がない。パフィアンの事例では直接実装の合格条件のほうが厳しく、全実行の監督を情報源の論文の共著者1人が担った。モデルの事前学習データに関連するコードが含まれていたかは確認できない、と著者自身が述べている。</p>
